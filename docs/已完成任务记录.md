### 12. 地图内 panorama 文字变实心色块 —— render attributes 交接修复（2026-09-22）

**现象**：`-panoramatest`（地图内托管视图）里所有 panorama 文字渲染成**标签色的实心矩形**（位置/宽度对，没有字形），
且用户实测"**只有闪的那几帧能看到文字**"。同一引擎跑 `+panorama_menu se_font_test.xml`（不在图里）时文字正常。

**排查结论（逐条排除）**：字体集合（33 个 `.vfont`，`CreateCustomFontfileReference` 全成功）、字体图集 CPU 内容
（导出 BMP 核对：`A control Stratum2…`/`中文字体测试 日本語` 等字形完整）、整图上传（`ATLASUP` 覆盖率单调增长）、
显存内容（`se_atlas_marker 2` 渐变标记能在屏幕上看到）、着色器 ALPHA 分支数学 —— **全部正常**。

**根因**：render attributes 的交接。CS:GO 把**真实的对象指针**交给渲染上下文，并且**直通下发**：

```cpp
// CSGO2019/panorama_s1wrapper/wrap_render.cpp:94
((CRenderContext*)pSrc2RenderContext)->m_pAttr = (CRenderAttributes *)pAttributes;
// CSource2Surface::DrawFancyQuad() 随后 PanDxDrawFancyQuads(...) 立即绘制，指针全程有效
```

移植版走 Source 1 材质系统（绘制会**成批延迟**），于是改成"拷贝到静态存储"，但只有
`SE_ATTR_STORE_PANORAMA`/`FANCYQUAD` **两个槽**（按材质分）→ 同一材质的每次绘制互相覆盖，着色器读到的是
最后一次写入的属性。

**探针证据**（`D:\cstrike\se_attr_probe.txt`，`ATTRSET`=渲染器每次绘制写入 / `ATTRREAD`=着色器实际读到）：

| | 修复前 | 修复后 |
|---|---|---|
| 请求文字 alpha 路径（`ATTRSET nType=2`） | 123 | 121 |
| 着色器真正拿到 `texType=2` | **4** | **114** |
| 着色器拿到 `texType=0`（无纹理→纯色块） | 156 | 44 |
| 两端口令地址 | 写入恒为池对象、读取恒为静态槽（**不同对象**） | 每次绘制各不相同 |

时间戳还证实了延迟是**成批**的（前几笔差 0.8–7.7ms，随后 156 笔填充期间着色器未读取）。

**修法**（`docs/临时方案与待改项.md` 同步登记）：**每次绘制一份属性副本**，存于一次性分配的平坦数组
（地址永不变动），在**帧边界**回收 —— `CSource2Surface::BeginFrame()` → `CRenderContext::SERecycleAttrStore()`
（4ms 护栏，避免同一帧多个 surface 反复回收）。

* 第一次尝试用可增长容器（`CUtlVector`）→ **崩溃**：增长会重新分配，已交给材质变量的旧指针全部悬空（游戏在
  测试视图建好后 ~14s 死掉，无退出日志）。改为一次性分配后正常。
* 顺手修掉：`CMaterialSystem` 图集再生成器 BGRA 分支把 RGBA 图集按 **1 字节/像素**索引

### 13. 背包（塔科夫式）拖动 + 悬停详情 —— 输入层三个坑（2026-09-23）

**现象**：自创背包面板（`mods/panorama_test/.../se_backpack.xml`）里**拖不动物品**；悬停详情时有时无，用户实测
"只有鼠标左右点击才有"；且**分辨率越低，拖动落点偏移越远**。

**根因（全在移植的输入层，不在面板 JS）**

1. **这个 era 的 panorama 根本没有按下/松开事件**：全树只派发 `onactivate`（松开时触发），
   `onmouseover/out` 之外没有 `onmousedown/onmouseup` → JS 无法区分"按下"和"点击"，拖动无从开始。
2. **UI 的光标位置只在游戏没拿鼠标时才更新**：位置来自 `IE_AnalogValueChanged(MOUSE_XY)`
   （`inputsystem.cpp` 发，`engine/panoramaenginehandler.cpp::ProcessUserInput` 转成 `IE_LocateMouseClick`）。
   一旦按住鼠标键（拖动的全过程），该流停掉，UI 光标冻在按下点 → 拖动过程中落点不变、松手回原位。
3. **照 CS:GO 抢鼠标会连带掐掉点击**：`UiToolkitAPI.AddDenyAllInputToGame()`（CS:GO 主菜单的做法，
   `csgo_mainmenu.cpp:319`）让引擎置 `cl_mouseenable 0`，而配套的 `cl_mouseenable_buttons`
   （"鼠标关掉也保留按键"）在**本树的客户端只声明、没人读**（`game/client/in_mouse.cpp:117`）→
   按下事件一起消失（实测 `SE_PORT_MOUSEDOWN` 探针计数 0，点击/拖动全废）。已撤。
4. **手动换算光标位置会随分辨率漂**：用 `vgui::input()->GetCursorPosition()` + `Plat_ScreenToWindowCoords()`
   喂进 UI，在 1280x720 看着正常，800x600 却喂出**负坐标** → 正是用户说的"分辨率越低偏移越远"。

**修法**

* `panorama/controls/panel2d.cpp`：`OnMouseButtonDown/Up` 里补 `onmousedown`/`onmouseup` 的 JS 派发
  （对齐 CS:GO 的事件面）。
* `engine/panoramaenginehandler.cpp::RunFrame`：每帧读**输入系统自己的** `MOUSE_X/MOUSE_Y` 模拟量
  （`g_pInputSystem->GetAnalogValue`）并按 `IE_AnalogValueChanged(MOUSE_XY)` 喂给 UI —— 与真实鼠标移动
  **逐位一致**，不再有任何坐标空间/分辨率换算。位置没变就跳过（零成本）。
* `se_backpack.js`：悬停详情与拖动都由一条 `$.Schedule` tick 驱动（命中测试 + ghost 面板跟随），不再依赖
  这个移植里不稳的 `onmouseover`；拖动时 `CELL`（逻辑像素）与光标（设备像素）之间用**运行时标定**的
  `scale`（用背景格自身位置测出，失败不缓存）。
* **不再**调用 `AddDenyAllInputToGame`（见根因 3；代码里留了注释说明为什么不能走那条路）。

**证据**：用户实机验收（"可以了 tooltip 悬停修好了"、"好了"）；`engine.log` 里
`[SE port] 背包: 拖动 AWP (0,0) -> (6,6) 已放下`、`拖动 C4 Explosive (6,4) -> (6,5) 已放下`
（落点被占时正确回弹）；截图 `build/_grab_feed1_16s.png`（物品停在新格子）。

**遗留**：想把鼠标真正交给 UI（CS:GO 那条路）需要先把客户端的 `cl_mouseenable_buttons` 读起来；
见 `docs/临时方案与待改项.md` 第 8 节。
